# ADR-006: Android 版を GitHub の Releases で配り、案内を GitHub Pages に置く

| 項目 | 値 |
|------|-----|
| ステータス | 提案中 |
| 作成日 | 2026-11-17 |
| 作成者 | ino5043 / Claude AI |
| 影響範囲 | Android のビルドと署名、CI（.github/workflows/educards-*.yml）、案内のページ（educards/site） |
| 関連ADR | ADR-005（AI を 3 社から選べるようにし、API キーを安全な保管場所に置く） |

## 1. コンテキスト

持ち主から「Android に入れて動かしたい人向けに、方法をファイルとともにサイトに載せたい。脆弱性には気を付けて」という要望があった。

これまでは Codespace で手作りした APK を、持ち主が自分あてのメールで送っていた。この APK には次の問題があった。

- debug の鍵で署名していた（鍵は Codespace の中にあり、作り直すと変わる。変わると上書きで更新できない）
- リリース版の設定（AndroidManifest.xml）にインターネットの許可が無く、AI でのカード作りが動かなかった
- バックアップが既定のまま有効で、以前の版で平文で入れていた API キーがバックアップに入るおそれがあった
- どのコードから作ったかを、受け取った人が確かめる方法が無かった

## 2. 決定

1. **配り方:** GitHub の Releases に APK を置く。Google Play には出さない
2. **作り方:** タグ `educards-v1.2.3` を push すると、GitHub Actions が作る（`educards-release-android.yml`）。手元や Codespace で作った APK は配らない
   - テストが通らなければ作らない。pubspec.yaml の版の番号とタグが違えば止める
   - `--obfuscate` で中身を読み解きにくくする。読み解き用の表は Releases に置かず、Actions の成果物に 90 日だけ残す
   - 端末の種類ごとに分ける（arm64-v8a・armeabi-v7a・x86_64）。いつも同じ URL で最新版を取れるよう、版の番号なしの名前も置く
3. **署名:** 配布用の鍵を 1 つ作り、GitHub の秘密の値（環境 `android-release`）に置く。鍵のファイルはジョブの中で一時的に戻し、終わったら消す。リポジトリには入れない（.gitignore とテストで確かめる）。CI で鍵が無ければビルドを止め、debug の鍵では決して署名しない
4. **確かめる手段を付ける:** ファイルの指紋（SHA256SUMS.txt）、署名の証明書（signing-certificate.txt と説明文）、ビルドの出どころの証明（GitHub の attestation）
5. **端末での安全の設定:** インターネットの許可だけを持つ。バックアップと機種変更の引き継ぎからアプリのデータを外す。http 通信を禁止し、OS の証明書だけを信頼する
6. **案内:** `educards/site` の静的なページを GitHub Pages に置く。外部のスクリプト・画像・書体は読み込まず、Content-Security-Policy で禁止する。Web 版のアプリは、ブラウザで試せるデモとして `/app/` に置く（既定。外すこともできる）
7. **公開する場所:** GitHub Pages に独自ドメイン `educards.techf.biz` を付ける（DNS に CNAME を 1 行）。会社のサイト `techf.biz` の下（`techf.biz/educards/`）には置かない

## 3. 理由

### 配り方の比較

| 観点 | GitHub Releases | Google Play | メールで送る（今まで） |
|------|----------------|-------------|---------------------|
| 費用 | ◎ 無料 | ○ 登録料 25 ドル（1 回） | ◎ 無料 |
| 準備の手間 | ◎ すぐできる | △ 審査がある。新しい個人のアカウントは、公開の前に決まった人数での試験の期間が要る | ◎ |
| 入れる人の手間 | △ 提供元の許可、Play プロテクトの確認 | ◎ | △ 同じ |
| 本物か確かめる | ○ 指紋・証明書・出どころの証明 | ◎ ストアが保証 | ✗ 手段が無い |
| 更新の知らせ | △ 無い（ページを見に来てもらう） | ◎ 自動で更新 | ✗ |

**総合判断:** GitHub Releases。見本アプリとして、すぐに、費用なく配れることを優先する。人が増えたら Google Play を考える。

### バックアップを外す理由

- API キーは端末の鍵（Keystore）で暗号化しているため、別の端末に戻しても読めず、読み込みの失敗のもとになる
- 以前の版で平文で入れていたキーが、バックアップに残るのを防ぐ
- 代わりに、カードは「デッキをエクスポート」で書き出してもらう（案内のページに書く）

### 不採用にした案

- **debug の鍵のまま配る:** 鍵が作る場所によって変わり、上書きで更新できなくなる。だれが作ったかの保証にもならない
- **APK を Pages に直接置く:** 版ごとの管理と、指紋・出どころの証明を付けにくい
- **Play App Signing（Google に鍵を預ける）:** Google Play に出すときの仕組みで、今回は使わない
- **会社のサイトの下（`techf.biz/educards/`）に中継して置く:** 使う人が自分の API キーを入れるデモが、会社のサイトとブラウザの保存の場所を共有してしまう。会社のサイトの設定変更と本番への反映も要る

## 4. 結果・影響

| 観点 | 影響 |
|------|------|
| ✅ 本物か確かめられる | 指紋・証明書・出どころの証明の 3 つで確かめられる |
| ✅ 更新できる | 同じ鍵で署名するので、上書きで更新でき、カードや設定が残る |
| ✅ 安全の設定がテストで守られる | ネットの許可・バックアップ・http の禁止・鍵のファイルが無いことを、毎回のテストで確かめる |
| ⚠️ 鍵を失うと更新できない | 署名の鍵を失うと、同じアプリとして更新できなくなる。鍵とパスワードは GitHub の秘密の値とは別に、持ち主が安全な場所に控えを持つ |
| ⚠️ 入れる手間 | 提供元の許可と Play プロテクトの確認が要る。案内のページで手順を説明する |
| ⚠️ 機種変更でデータが移らない | バックアップから外したため。書き出しを案内する |
| ✅ 会社のサイトと分かれる | 別のドメインなので、デモに入れた API キーやカードが会社のサイトと混ざらない。会社のサイトには手を入れない |
| ⚠️ ページを公開する | Pages は誰でも見られる。載せるのはアプリの説明・入れ方・デモだけにする。API キーは埋め込まない |
| ⚠️ DNS の行に頼る | `educards` の CNAME を消すと開けなくなる。使わなくなったら Pages の独自ドメインの設定も外す（他人に取られないように） |

### 再検討の条件

- 使う人が増え、自動の更新やストアの保証が必要になったとき（Google Play）
- iOS 版を出すとき
- 署名の鍵が漏れた、または失ったとき
