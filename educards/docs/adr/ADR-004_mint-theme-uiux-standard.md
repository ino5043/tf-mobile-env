# ADR-004: ミントの配色と UI/UX 標準の適用

| 項目 | 値 |
|------|-----|
| ステータス | 提案中 |
| 作成日 | 2026-11-17 |
| 作成者 | ino5043 / Claude AI |
| 影響範囲 | EduCards のテーマ（lib/core/theme）と全画面の色・文字・角の丸み |
| 関連ADR | ORG-009（AI の色）、ORG-010（TF の色のトークン） |

## 1. コンテキスト

EduCards は 2026-03 に急いで作った見本アプリで、見た目は Flutter の標準のまま（青 #4A6CF7 を 1 色渡し、残りを自動で作る）だった。UI/UX 標準（00_tech-education-docs/00_開発標準/UIUX標準）との照合で、次が見つかった。

- 色を画面のコードに直接書いている箇所が多く、緑や橙の文字は 2.2〜2.8:1 で 4.5:1 に届かない
- エラーの赤を「期限のカード」や「もう一度」にも使っている（意味の色の転用）
- 10〜12px の文字がある
- 浮いた要素の境界を影だけで示している

あわせて、持ち主から「少しかわいく」「UI/UX を TF の標準に合わせたい」という要望があった。

## 2. 決定

1. **キーの色はミント（#00796B）にする。** TF の色のトークン（藍 #223A5E・丹 #E45E32、ORG-010）は使わず、アプリ独自の配色を持つ。DADS から変えてよい範囲（第 2 部 3.3）の中で値を決める
2. **トークンの正本は `lib/core/theme/app_tokens.dart` の 1 か所にする**（3-2）。画面のコードは `colorScheme` と `AppColors`（ThemeExtension）だけを使い、色を直接書かない（3-1・3-3）。これはテストでも確かめる
3. **評価ボタンと習熟度は、意味の色ではない専用の役割にする**（4-4）。評価ボタンはミントの濃淡の 4 段、習熟度は灰・ピーチ・空色・ミント。どちらも文字と組で使う（4-3）
4. **「かわいさ」は角の丸みと薄い面で出す。** ボタンと札は丸く（全丸）、カードは 20、フラッシュカードとダイアログは 24。影はやめ、枠線で境界を示す（3-11）
5. **変えないもの:** コントラスト（文字 4.5:1・文字以外 3:1）、フォーカスの表示（DADS の黄 #FFD43D と黒）、意味の色の色相（エラーは赤、警告は黄）。紫は AI の目印の色（ORG-009）なのでキーの色にしない
6. **書体は Noto Sans JP を優先し、無い端末では OS の日本語書体を使う**（5-1）。書体ファイルは同梱しない
7. **暗い表示の色も決め、明るい表示と同じ基準で計算する**（4-7）

コントラスト比の計算結果は `docs/design/color-contrast.md` に記録する（3-5）。

## 3. 理由

### キーの色の比較

| 観点 | A コーラルピンク | B ミント | C ピーチ | D 空色 | TF のトークン |
|------|----------------|---------|---------|-------|--------------|
| かわいさ | ◎ | ○ | ○ | △ | △（硬め） |
| 長く使っても疲れにくい | ○ | ◎ | ○ | ◎ | ○ |
| 意味の色と紛れない | △ エラーの赤に近い | ○ 成功の緑に近いが色相が違う | ○ | ◎ | ○ |
| 学習・テストの場面との相性 | △ 赤は「不正解」を連想させる | ◎ | ○ | ◎ | ○ |

**総合判断:** B ミント。持ち主が色見本（4 案を同じ画面に当てたもの）を見て選んだ。暗記に効く色はあるかという問いについては、基調の色そのものの効果は根拠が弱く（赤と青の効果の研究は、後のメタ分析で支持が少ない）、効くのは「覚える対象を目立たせる（孤立効果）」と「色の意味をいつも同じにする」ことなので、基調は長く使っても疲れにくい色を選んだ。覚える対象（カードの表の用語、穴埋めの空欄）はキーの色と太字で目立たせる。

### 不採用にした案

- **TF の色のトークン（藍と丹）をそのまま使う:** 業務画面向けの硬い印象で、「少しかわいく」と合わない。また、ツールを組織に中立にする方針（組織に固有のことは 00_org の設定に置く）があり、見本アプリに組織の色を埋め込まないほうがよい
- **シードの色から自動で作る（M3 の colorSchemeSeed）:** 出る値をこちらで決められず、コントラストの記録（3-5）が残せない
- **丸ゴシックの書体:** 5-1（Noto Sans JP）の例外になる。今回は見送り、角の丸みでかわいさを出す
- **書体ファイルを同梱する:** Noto Sans JP は 1 つの太さで数 MB あり、見本アプリには重い

## 4. 結果・影響

| 観点 | 影響 |
|------|------|
| ✅ 標準への準拠 | 色・文字・境界・フォーカスの必須の規則を満たす。満たしていることをテスト（test/core/theme/app_theme_test.dart）で毎回確かめる |
| ✅ 変えやすさ | 色の正本が 1 か所になり、配色を変えるときは app_tokens.dart だけを直せばよい |
| ✅ 覚えやすさ | 覚える対象が目立ち、習熟度の色がどの画面でも同じになる |
| ⚠️ TF のトークンと別の系統 | design-system.json の値が変わっても EduCards には反映されない。TF のブランドを見本アプリに出したくなったら、この ADR を見直す |
| ⚠️ 書体が端末によって違う | Noto Sans JP が無い端末（iOS など）では OS の書体になる |
| ⚠️ フォーカスの表示は近似 | Flutter では DADS の二重線（外側の黒 4px と内側の黄 2px）をそのまま作れないため、黒の 3px の線と黄の面で近づけている |

### 再検討の条件

- TF のブランドを見本アプリに出す方針になったとき
- 書体を同梱できる容量の余裕ができたとき、または丸ゴシックを例外として認めるとき
- UI/UX 標準にモバイル向けの章ができたとき
