# ADR-005: カード作りの AI を 3 社から選べるようにし、API キーを安全な保管場所に置く

| 項目 | 値 |
|------|-----|
| ステータス | 提案中 |
| 作成日 | 2026-11-17 |
| 作成者 | ino5043 / Claude AI |
| 影響範囲 | AI でのカード作り（lib/features/deck/data/services）、設定（lib/features/settings）、API キーの保存 |
| 関連ADR | ADR-002（Hive によるオフラインファースト設計） |

## 1. コンテキスト

EduCards の AI でのカード作りは Claude だけに対応していた。持ち主から「Claude・ChatGPT・Gemini を選べるようにしたい」という要望があった。利用者がすでに持っている AI のキーを使えれば、試してもらいやすくなる。

あわせて、次の問題があった。

- API キーを通常の設定（Hive の箱）に暗号化せずに入れていた。tf-mobile-env の mobile-security ルール（3. シークレット管理）は、キーを端末の安全な保管場所（Keystore・キーチェーン）に置くよう求めている
- 中心の部分（ユースケース）が、通信の部分（AIGenerationService）を直接読み込んでいた（PR #4 のレビューで残った設計の指摘）
- このあと Android 版を一般に配る予定があり、配る前にキーの扱いを固めておく必要がある

## 2. 決定

1. **AI は Claude・ChatGPT（OpenAI）・Gemini（Google）の 3 社から選べるようにする。** 既定は Claude
2. **中心の部分には「カードを作る係」の窓口（`CardGenerator`）だけを置く。** 3 社の違い（URL、キーの渡し方、送る形、返答の読み方）は data 層の `AiTextClient` の実装に閉じ込める。指示文と返答の読み取りは 3 社で共通にする（`card_prompts.dart`）
3. **使うモデルは次にする**（2026-11 時点。値は `api_config.dart` の 1 か所で持つ）

   | 会社 | API | モデル |
   |------|-----|--------|
   | Anthropic | Messages API | claude-sonnet-5-5 |
   | OpenAI | Responses API | gpt-6.1-terra |
   | Google | generateContent（v1beta） | gemini-3.8-flash |

4. **API キーは AI ごとに、端末の安全な保管場所（flutter_secure_storage）に置く。** 以前 Hive に入っていた Claude のキーは、起動時に一度だけ移してから消し、Hive のファイルを詰め直して消し切る
5. **保存したキーは画面に戻さない。** 入力欄は常に空から始め、「保存済み」とだけ示す。キーボードの予測と自動修正は切る
6. **送る前に確かめる。** ファイルは画像（JPEG・PNG・GIF・WebP）と PDF だけ、15 MB まで（3 社で一番小さい Gemini の上限に合わせる）
7. **会社に渡す情報を最小にする。** Gemini のキーは URL ではなくヘッダーで渡す。OpenAI には返答を保存しないよう頼む（`store: false`）。エラーの文に入れる API の返答は 300 文字までにする

## 3. 理由

### AI の会社の選び方の比較

| 観点 | Claude だけ（今まで） | 3 社から選ぶ | 中継のサーバーを立てる |
|------|---------------------|-------------|---------------------|
| 試してもらいやすさ | △ Claude のキーが要る | ◎ 持っているキーで試せる | ◎ キーが要らない |
| 費用 | 利用者が払う | 利用者が払う | △ 持ち主が払う |
| 作りの複雑さ | ◎ | ○ 係が 3 つになる | △ サーバーの運用が要る |
| キーの安全 | ○ 端末の中だけ | ○ 端末の中だけ | ◎ 端末に置かない |
| オフラインファースト（ADR-002） | ○ | ○ | △ サーバーに頼る |

**総合判断:** 3 社から選ぶ。見本アプリにサーバーの運用は重く、費用を持ち主が負うのも合わない。

### キーの保存場所の比較

| 観点 | Hive（今まで） | Hive を暗号化 | flutter_secure_storage |
|------|---------------|--------------|----------------------|
| 暗号化の鍵の置き場所 | なし（平文） | △ 鍵を別に守る必要がある | ◎ OS が守る（Keystore・キーチェーン） |
| mobile-security ルール | ✗ | △ | ◎ |
| Web 版 | 平文 | 鍵も同じブラウザ | △ 暗号化するが、鍵も同じブラウザ |

### 不採用にした案

- **OpenAI の Chat Completions API:** PDF をそのまま渡しにくく、新しい機能は Responses API に入るため
- **証明書ピンニング（mobile-security ルール 2）:** 相手は 3 社の公開 API で、証明書は会社の都合で入れ替わる。ピン留めすると、入れ替えのたびにアプリが使えなくなる。OS の証明書の確認に任せる
- **会社ごとに考える量（effort・thinking）を細かく変える:** 3 社で名前と効き方が違い、モデルが変わると使えなくなることがある。Claude だけ effort low を指定し、ほかは既定にする

## 4. 結果・影響

| 観点 | 影響 |
|------|------|
| ✅ 試してもらいやすさ | 持っている AI のキーで使える。Gemini は無料の枠で試せる |
| ✅ キーの安全 | Android では Keystore で暗号化して保存する。画面にもログにも出さない |
| ✅ 設計 | 中心の部分が通信の部分を直接知らなくなった（窓口に頼る形） |
| ✅ 変えやすさ | 会社やモデルを増やすときは、係を 1 つ足して `api_config.dart` を直せばよい |
| ⚠️ 保守の手間 | 3 社のモデルの提供終了を見張る必要がある（Claude は 2026-06 に旧モデルが終了した前例あり） |
| ⚠️ 品質の差 | 同じ指示文でも、会社によってカードの出来が違うことがある |
| ⚠️ Web 版のキー | ブラウザの中に暗号化して置くが、鍵も同じブラウザにあるため、端末の保管場所ほど強くない。共用のパソコンでは使わないよう案内する |
| ⚠️ 未確認 | ChatGPT と Gemini は、本物のキーでの生成と、Web 版でブラウザから直接呼べるか（CORS）をまだ確かめていない |

### 再検討の条件

- どれかの会社が、ブラウザや端末から直接呼ぶことを禁止したとき
- 利用者にキーを用意してもらうのが難しく、中継のサーバーが必要になったとき
- 使っているモデルが提供終了になったとき
